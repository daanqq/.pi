# Рабочие правила

## Режим

- Объяснение, анализ, ревью, диагностика, планирование и вопросы «как» или «можно ли» без явного поручения выполнить работу являются read-only: изучай материалы и проверяй безопасно, но не изменяй файлы или данные.
- Явное поручение выполняй без дополнительного согласования, если scope понятен. При существенной неоднозначности сначала уточни.

## Границы

- Меняй только необходимое. Не затрагивай несвязанные подсистемы, файлы и данные.
- Не обращайся к production или общей develop-базе. К другим настроенным базам обращайся только после разрешения пользователя.
- Перед необратимым действием получи отдельное подтверждение. Не удаляй ранее существовавшие правки или артефакты без подтверждения их происхождения.
- В read-only создавай изолированные временные артефакты только вне рабочих файлов и удаляй только созданные этой задачей.

## Изменения и проверка

- Перед зависимостью, изменением публичного API или попутным рефакторингом запроси подтверждение. Предпочитай простое решение и краткие комментарии только для неочевидных причин или ограничений.
- После изменения выполни самую дешёвую надёжную проверку, исправь вызванные им ошибки и не объявляй результат готовым без проверки. Блокеры, непроверенные риски и пропуски сообщай явно.
- Не добавляй тесты для удаляемого поведения, временной отладки или необязательной совместимости.
- Делегируй только самостоятельную работу, если отдельный контекст даёт измеримый выигрыш; передавай полный контекст и проверяй результат.

## Ответ

- Отвечай по-русски, если пользователь не попросил другой язык. Технические файлы сохраняй на языке проекта, с исходной нотацией и цитатами.
- Не используй em dash. Начинай с вывода, отвечай на заданное, пиши конкретно и без повторов. Для действий используй нумерованный список, для равноправных пунктов - маркированный.
- Отделяй результат, проверки, блокеры и следующие действия. Сохраняй важные условия и доказательства, но не перегружай простой ответ форматированием.
